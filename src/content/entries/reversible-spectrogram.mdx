Spectrogram 常被当成一张图看。它其实是一份采样矩阵：横轴是帧，纵轴是频点，每个像素是一次 STFT 之后的某个频率分量。看得懂这张图，就能把它变回声音。问题只剩一个：存多少才够。

## 参数怎么选

输入先转单声道并重采样，再用 Hann 窗做 STFT，`hop = win / 4`。四倍重叠同时管住两件事：图片尺寸别失控，相位重建有足够的冗余约束。实测两倍重叠会明显损坏长窗的包络，八倍重叠只是把图撑大，没有稳定收益。

窗长三档：256、512、1024。

幅度按 dB 映射到字节。紧凑模式继续量化到 2、4 或 8 bit；位深只改变有效档数，不改变内存里的元素类型。可逆模式用固定的 120 dB 标度，并把相位存成 `cos(φ)` 与 `sin(φ)` 两段：折叠角在 2π 边界上不连续，直接存角度会在那一圈留下接缝。

图像有两道上限。一是 1600 万像素，管住时间与内存成本；二是单边 65535 像素，避开浏览器 canvas 静默失败的那一段。编码器用同一份几何函数挑出能容纳输入的最高配置，近似像素数是 `样本数 × 重叠倍数 / 2`，与窗长无关。短窗更早撞上宽度上限，长窗留给长音频。

## 还原走哪条路

| 输入 | 路径 |
| --- | --- |
| 相位可靠 | 直接逆 STFT |
| 无相位或弱相位 | PGHI 初始化，再用 RTISI-LA 迭代 8 次 |
| 用户要求精修 | RTISI-LA 16 次，再有预算上限的锚定 Griffin–Lim |

直接逆变换保留 PNG 里的相位，是可逆图的最佳路径。对可靠相位继续迭代反而会降低波形一致性，这一点常被反过来理解。

紧凑图的相位已经丢了，任何算法都只能找一个与幅度谱一致的波形，找不回来的东西也谈不上还原。PGHI 给出确定的初相位，RTISI-LA 用逐帧前瞻压掉爆音。精修主要降低频谱误差，不保证提高与原波形的相关性。

低位深下，最低量化档表示「低于阈值」，不表示幅度正好落在档中心。重建对这一档放宽下界，避免人为铺出一层噪声地板。8 bit 的动态范围够大，走原路径。

## 实测

六段素材、每段前 8 秒，中位数如下。「相关」是与原波形对齐后的相关系数，LSD 是谱失真。

| 模式 | 图片链路 | 相关 | LSD |
| --- | --- | ---: | ---: |
| 紧凑 8k / 4 bit / win 256 | PNG | 0.466 | 10.2 |
| 紧凑 8k / 8 bit / win 512 | PNG | 0.299 | 3.5 |
| 可逆 / 原采样率 / win 512 | PNG | 1.000 | 0.3 |
| 可逆 / 原采样率 / win 512 | JPEG | 0.745 | 4.2 |
| 可逆 / 原采样率 / win 512 | 缩放 0.75× | 0.112 | 4.5 |

这些数只描述这组素材和参数，但支持三个结论：原始可逆 PNG 近乎无损；JPEG 会明显压低相位价值，通常还留得下方向；缩放会迅速摧毁可逆性。紧凑模式的目标是能读、能听、体积小。

短窗的 RTISI 对浮点微扰敏感。单个输入值差 1 ulp，也可能收敛到另一个有效波形。所以改数值时要比较分布、谱误差和包络，不能拿单条素材的相关性升降下结论。可逆路径反过来，要求逐样点等价，验证方式完全不同。

## 边界画在哪

MoonBit 内核接手高频、形状稳定、能在同一块线性内存里连续跑完的部分：FFT、STFT 帧操作、PGHI、RTISI-LA 与元数据位流。图片 DOM、Web Audio、格式路由和低频控制留在 TypeScript。这条线避免为了几毫秒收益引入跨线程复制、对象生命周期或第二套业务规则。

格式本身冻结了：图片元数据数组的第一个元素是版本号，字段只增不改、永不重排。今天做出来的图，以后任何版本都还能读出来。
